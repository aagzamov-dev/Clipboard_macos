# Clipboard 1.0.4

- Add **Restart Clipboard** to Settings → Permissions (also available in General’s permission controls). After granting Accessibility access, recheck access or restart without finding the app again manually.
- Restart protects unsaved clipboard edits using the existing Save/Discard/Cancel flow, waits for the original process to exit, then opens the same app directly to Permissions.
- Backup/import operations and active paste tests block restart. The app stays running if its restart helper cannot get ready, and the helper does not open another copy if the original fails to exit.

Use **Check for Updates…** to install this release. Your history and preferences remain outside the application bundle.

## Permission limitations

This release remains **ad-hoc signed, not Developer ID signed or notarized**. Updating may invalidate an older Accessibility grant. Restarting refreshes permission recognition; it cannot grant access or preserve permissions across ad-hoc updates. If access stays blocked, remove the old Accessibility entry and add the exact running app again. Consistent Developer ID signing remains the planned solution for stable publisher identity.

The update archive and appcast retain the existing Ed25519 signing key. No new privacy permissions are requested.

## Verification

Automated tests cover restart-button routing, busy paste-test protection, parent-process validation, readiness failure, waiting for exit, timeout without opening a duplicate, and one launch attempt on failure. The release pipeline also runs storage/native tests, compiles UI tests, builds both architectures, verifies checksums, and checks update signatures including tamper rejection.

No app was launched, restarted, or replaced on the development Mac. Live relaunch and permission recognition on that installation remain untested; OS/hardware compatibility and Instruments coverage remain as documented in VERIFICATION.md.
